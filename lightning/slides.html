Claude forgets everything. Mine doesn't.

A conversation memory for Claude Code — every session you've ever had, searchable from inside the next one. Runs entirely on your laptop.

The problem

You have had this conversation before.

  • Context window fills. Auto-compaction fires. The reasoning is gone, the summary is not the same thing.
  • New day, new session — you re-explain the codebase, the conventions, the constraints.
  • Six weeks ago you and Claude solved this exact bug. Neither of you remembers how.
  • "Why is it done this way?" The answer was in a session you closed in March.
The thing nobody says out loud

Your best design docs are the conversations you never wrote down.

Every trade-off you talked through, every "no, do it this way, because…" — captured in full, then thrown away when the session ended.

What I built

A hook, a database, and three MCP tools.

Capture

Every message, automatically

A Claude Code hook fires on each prompt and at session end. No plugin, no remembering to save.

Store

Postgres + pgvector

Each message embedded as a vector, plus a full-text index. One Docker container.

Recall

Claude searches its own past

An MCP server exposes the archive as tools. Claude decides when to look things up.

In practice

You just ask.

you What did we decide about retry backoff on the ingest worker?
claude → search_memory("retry backoff ingest worker")Three hits, the closest from 14 March…
14 Mar nakomis/ingest · branch: spike-retries · 5 months ago"…so exponential is wrong here — the downstream is rate-limited per minute, not per request. Fixed delay of 20s, cap at 5 attempts, then DLQ."

It found a decision you made before the repo had a README.

The three tools

Small surface, on purpose.

search_memory

Hybrid search — semantic similarity and full-text, fused. Returns the matching messages with the turns either side, so the answer arrives with its context.

get_conversation

Pull a whole session back by id. This is the compaction rescue: the detail the summary dropped is still there, verbatim.

list_recent_sessions

What was I working on? Newest first, filterable by project path.

Under the hood

Four moving parts, all on your machine.

No server. No account. No network call that leaves the box.

The part your security team will ask about

Nothing leaves your laptop.

Default

Ollama, locally

Embeddings are computed on your machine by a local model. Your conversations are never sent anywhere — not to me, not to a vendor, not to a cloud region.

If you'd rather

Bedrock or OpenAI

Both supported, both opt-in. Worth knowing that choosing them does send message text to that provider to be embedded.

The database is a container on localhost:5433. The archive is a directory in your home folder. That is the whole trust boundary.

One design decision worth stealing

The first version lost messages, silently.

The hook wrote straight to Postgres. When Docker was down the write threw, the exception was swallowed, and the message was simply gone. No error. No log line. You find out weeks later, looking for something that was never there.

# the worst four lines in the original
try:
    write_to_postgres(messages)
except Exception:
    pass  # ← a conversation just died here
The fix

Split what must not fail from what may.

Must not fail

Capture

The hook appends to a local SQLite file. No network, no credentials, no daemon — nothing that can be "down".

Allowed to fail

Delivery

A drainer moves it into Postgres later. If that fails, the queue simply grows and drains next time.

Durable mode is the default for exactly this reason. Direct mode — write straight through — is one flag away if you'd rather have fewer moving parts.

Getting it

One script. Ten minutes.

# needs docker, uv, python 3.11+, and ollama
git clone https://github.com/nakomis/claude-chats
cd claude-chats/localhost
./install.sh
  • Starts Postgres, pulls the embedding model, wires up the hook and the MCP server.
  • Asks which capture mode you want. Re-run it to change your mind.
  • Restart Claude Code and it is already recording.

Every step is idempotent — re-running is always safe.

Being straight with you

What it costs.

  • Disk. Text is cheap; the vectors are not. Budget a few hundred MB per year of heavy use.
  • A couple of minutes' lag in durable mode before a message becomes searchable. Force it with --drain if you're impatient.
  • It records everything you type at Claude. Including the things you paste. Know that before you install it on a work machine.
  • Recall is only as good as the embedding model. Full-text search covers for it when the phrasing is exact.
